# s-tcg

**s-tcg** 是一个面向集换式卡牌游戏（TCG）的本地辅助工具项目，目前聚焦 Weiß Schwarz（WS）斩杀概率计算。用户输入对手的牌库、弃牌区、等级区、时计区状态，以及按顺序执行的伤害、摩卡和掏底操作，程序精确计算对手败北概率。

> 本项目处于早期开发阶段。当前实现 WS 基础概率计算、摩卡和两类掏底操作，不是完整对局模拟器，也不应被视为正式比赛裁定工具。

## 功能

- 精确概率传播，内部以 Python `Fraction` 保留有理数结果；不使用蒙特卡洛近似。
- 分别报告升至 4 级败北、无法刷新败北、总败北和完成全部操作后的存活概率。
- 支持普通伤害、摩卡和两种掏底的混合有序操作，如 `2-摩卡2-掏底条件4-2-掏底计次5-3`。
- 前端提供操作序列构造器，可添加、排序和删除伤害、摩卡及掏底操作。
- 提供 JSON API，纯数字旧伤害序列格式继续兼容。
- 仅依赖 Python 标准库；无需数据库、账户或第三方服务。

## 快速开始

### 环境

- Python 3.10 或更新版本（开发和测试已在 Python 3.14 环境验证）。
- 无需 `pip install`，目前没有第三方 Python 依赖。

### 启动本地服务

```bash
python run.py
```

浏览器访问 <http://127.0.0.1:8000>。默认只监听本机回环地址；按 `Ctrl+C` 停止服务。

页面是单文件原生 HTML/CSS/JavaScript，不需要 Node.js 构建步骤。

## Windows 单文件 EXE

普通用户可以直接运行发布包中的 `s-tcg.exe`，无需安装 Python 或任何 Python 包。程序会在本机随机空闲端口启动服务、尝试自动打开浏览器，并在控制台显示访问地址；按 `Ctrl+C` 或关闭程序窗口即可停止服务。EXE 仅监听本机回环地址，不作为局域网/公网服务器使用。排查问题时可从终端以 `s-tcg.exe --no-browser` 启动，此参数会跳过自动打开浏览器并在终端打印地址。

单文件 EXE 首次启动需解压内嵌运行时，可能比源码启动稍慢。未签名构建可能触发 Windows SmartScreen 或杀毒软件的未知应用提示；用户应只从可信发布渠道获取程序。项目目前没有代码签名证书或自动更新器。

在 Windows 上自行构建 EXE 时，开发者需准备 Python 3.11 和 PowerShell：

```powershell
.\build_windows.ps1
```

脚本会创建 `.venv-build311` 隔离环境、安装锁定版本的构建工具，并生成 `dist/s-tcg.exe`。可选参数 `-Clean` 会让 PyInstaller 清理自身缓存后重建；`-SkipInstall` 仅适用于已准备好隔离构建环境的情况。构建机需要联网安装 Python 构建工具；构建完成后，目标用户运行 EXE 不需要 Python 或联网。EXE 必须在对应目标操作系统上分别构建；当前脚本只构建 Windows x64 版本。

PyInstaller 是构建期依赖，不是项目运行依赖。构建工具锁定版本见 [`requirements-build.txt`](requirements-build.txt)。

## 输入说明

页面需要以下状态：

| 输入 | 示例 | 含义 |
| --- | --- | --- |
| 牌库数量 / 高潮数 | `25 / 4` | 当前牌库总数及其中高潮数量 |
| 弃牌区数量 / 高潮数 | `15 / 2` | 当前弃牌区总数及其中高潮数量 |
| 等级-时计 | `1-4` | 等级区 1 张、时计区 4 张 |
| 时计高潮数 | `0` | 时计区高潮数量，必填 |
| 操作序列 | `2-摩卡2-掏底条件4-2-掏底计次5-3` | 从左至右执行的操作 |

操作序列中的正整数表示普通伤害；`摩卡x` 表示查看牌库顶最多 `x` 张；`掏底条件x-y` 表示掏底 x 张，含高潮则造成 y 点伤害；`掏底计次x-z` 表示每张掏出的高潮造成一次 z 点伤害。首版掏底 x 最大 5，条件伤害 y 最大 4，计次伤害 z 最大 50；计次伤害次数等于本次掏出的高潮数，最多为掏底张数 x（即最多 5 次）。

## API

### `POST /api/ws/lethal-calculations`

文本操作序列请求示例：

```json
{
  "deck_count": 25,
  "deck_climax": 4,
  "waiting_count": 15,
  "waiting_climax": 2,
  "level_clock": "1-4",
  "clock_climax": 0,
  "operation_sequence": "2-摩卡2-掏底条件4-2-掏底计次5-3"
}
```

`level_clock` 可以用 `level` 和 `clock` 两个整数替代。操作序列也可传结构化数组：

```json
"operation_sequence": [
  {"type": "mocha", "look": 2},
  {"type": "damage", "points": 3},
  {"type": "bottom_conditional", "mill": 4, "damage": 2},
  {"type": "bottom_per_climax", "mill": 5, "damage": 3}
]
```

纯伤害旧格式仍可通过 `damage_sequence: "2-2-3-4"` 发送。成功响应包含概率的十进制百分比、最简分数、规则/模型版本及模型假设；非法输入以 HTTP 400 和 `INVALID_INPUT` 返回。

### `GET /api/ws/rules`

返回当前规则/模型版本及支持范围，如最大牌库数量、摩卡查看上限、时计阈值和败北等级。

## 运行测试

```bash
python -m unittest discover -s tests -v
```

测试覆盖伤害取消、刷新、时计升级、摩卡、两种掏底操作、掏底途中刷新（刷新点所代表的 1 点伤害只结算一次）、输入校验、API 路由和小牌库穷举交叉验证。修改规则或状态转移时，必须补充对应测试，并确认总概率为 1。

## 规则与模型边界

工作规则记录在 [`docs/ws_rule.md`](docs/ws_rule.md)，模型假设和开发细节记录在[开发计划](docs/WS斩杀概率计算器开发计划.md)。当前实现有意限制在普通牌/高潮两类和已建模区域，不代表完整 WS 规则。

- 命中判定确认后，普通伤害牌逐张进入时计；每张牌进入后都检查 7 张升级阈值。升级后未处理的命中牌继续进入更新后的时计。
- 高潮会取消当前伤害；刷新点高潮不取消正在进行的伤害。
- 时计升级时默认由防守方选择最有利于存活的合法牌。
- 摩卡随机查看牌库顶最多 `x` 张；看见牌后，由进攻方选择弃掉 0 至 `x` 张，并任意排列留下牌的牌顶顺序。默认决策目标是最大化对手败北概率。
- 摩卡查看本身不触发刷新；牌库不足 `x` 张时查看现有全部牌。
- 掏底卡逐张进入弃牌区。途中牌库耗尽时，刷新当前弃牌区（包括本次此前掏出的卡），将刷新点放入时计并检查升级；该刷新点就是规则要求的 1 点伤害，不额外重复结算，然后继续当前掏底。刷新前已掏的卡可能被再次掏出，并再次计入掏出卡次。
- 条件掏底只要本次掏出的卡次中包含高潮便造成一次声明伤害；计次掏底按高潮掏出卡次造成伤害，每次独立判定，次数不超过本次掏底张数（最多 5 次），没有独立的 4 次上限。
- 刷新点若使时计达到 7，当前模型按“先立即升级，再继续当前伤害”处理。这是工作假设，尚需规则审核者确认。
- 不模拟卡牌文本效果、完整对局、触发区、舞台/手牌/库存等未输入信息，也不覆盖特殊赛制。

结果是**相对于这些输入与假设的条件概率**。使用前请核对区域数量和高潮数量；若模型假设不符合具体卡牌或裁定，结果可能不适用。
