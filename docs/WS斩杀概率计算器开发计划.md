# WS 斩杀概率计算器：规则分析与开发计划

> 本文档将 `ws_rule.md` 和用户提出的使用场景转化为首版可执行范围。概率含义是：在输入的当前区域构成、指定伤害序列和本文确认的结算规则下，对方在全部伤害结算结束前败北的概率。若规则前提变化，需更新规则版本、计算器和测试样例。

> 执行约定：本轮开发计划只以仓库内 `docs/ws_rule.md` 为规则依据，不补充外部资料。`ws_rule.md` 未描述的操作按本文明确标注的首版建模假设处理；若要把结果用于正式比赛裁定，应先由规则审核者确认这些假设。

## 0. 继续执行的开发路线

当前仓库只有规则和设计文档，尚无计算器代码。按依赖顺序推进，不先引入框架或数据库：

1. **冻结可编码规则**：补齐时计高潮数输入；按本地规则文字确定升级检查点；把仍无法从本地规则推出的内容作为有记录的假设。
2. **实现纯 Python 精确计算核心**：先写输入模型、区域状态转移和精确概率传播，不依赖 Web 框架。
3. **用小状态穷举对拍**：覆盖取消、命中、刷新、刷新点和升级选择，确认概率质量守恒。
4. **再实现 API 和页面**：只有核心与测试稳定后，才确定并引入服务框架；页面让用户能明确输入时计高潮数量并读懂结果。
5. **端到端验收及文档更新**：用 `2-2-3-4` 等场景验收输入、结果含义和假设展示。

首个可运行交付物应是本地命令/测试可调用的概率引擎；API 和页面是后续阶段，不是概率正确性的前置条件。

## 1. 功能目标

用户输入对手当前牌库卡牌数及其中高潮数量、弃牌区卡牌数及其中高潮数量、当前等级/时计状态（例如 `1-4`）、时计区高潮数量，以及我方依次造成的伤害序列（例如 `2-2-3-4`）。应用精确计算在整组伤害的所有结算过程中（包括最后一段伤害的结算时点），对手等级达到 4 或因规则规定的无牌可刷新而败北的总概率。

默认不模拟完整对局、角色效果、对手防御能力、触发区或卡牌检索/洗切效果；首版输入表示一次计算开始时的已知区域状态。

## 2. 输入、输出与有效性

### 2.1 首版输入

| 字段 | 含义 | 校验要求 |
| --- | --- | --- |
| 牌库总数 `deck_count` | 对方当前牌库中的卡牌数 | 整数，范围 0–50 |
| 牌库高潮数 `deck_climax` | 当前牌库中的高潮卡数量 | 整数，`0 ≤ deck_climax ≤ deck_count` |
| 弃牌区总数 `waiting_count` | 对方当前弃牌区卡牌数 | 整数，范围 0–50 |
| 弃牌区高潮数 `waiting_climax` | 当前弃牌区中的高潮卡数量 | 整数，`0 ≤ waiting_climax ≤ waiting_count` |
| 当前等级 `level` | 对方等级区卡牌数 | 整数，0–3；输入 4 视为已败北 |
| 当前时计 `clock` | 对方时计区卡牌数 | 整数，0–6；输入 7 及以上应按规则归一结算或提示状态无效，首版建议拒绝并提示先处理升级 |
| 时计高潮数 `clock_climax` | 当前时计区内的高潮卡数量 | 整数，`0 ≤ clock_climax ≤ clock`；精确计算升级和后续刷新所必需 |
| 操作序列 `operation_sequence` | 依次执行的伤害/卡组破坏操作，例如 `2-2-3-4` 或 `摩卡2-3` | 至少一个操作；普通伤害为正整数；摩卡 `x` 为 1–10；总操作不超过 50 |

输入数据还应满足已知区域卡牌数 `deck_count + waiting_count + clock + level ≤ 50`，以及已知区域高潮总数 `deck_climax + waiting_climax + clock_climax ≤ 8`。该校验按标准 50 张、最多 8 张高潮构筑；未来若支持特殊赛制，应使用对应赛制参数，而非移除校验。

### 2.2 需要明确补充/约定的状态

1. **当前时计区的高潮数量**：必须新增为输入。时计升级后，未放入等级区的牌进入弃牌区，会改变下一次洗牌中的高潮比例；不知道时计区高潮数，就无法精确计算后续伤害概率。
2. **时计升级的选牌策略**：规则允许玩家选择进入等级区的牌，而未进入等级区的牌会进入弃牌区并影响后续洗牌。因此首版将“斩杀概率”定义为对手采用最有利于存活的合法选择；计算器在每次升级时分别评估可选择的普通牌/高潮牌分支，选择能使后续存活概率最高的动作。若需模拟固定或随机策略，作为后续策略选项，不能暗中假定。
3. **败北边界**：按文档，升入等级区后达到 4 立即败北；伤害序列在败北瞬间停止，后续段数不再结算。
4. **伤害翻开的暂存牌**：一段伤害可能跨越洗牌刷新。当前伤害尚未结算的已翻牌不属于弃牌区，不可并入刷新洗牌；取消时整段暂存牌（含触发取消的高潮）进入弃牌区，命中时整段普通牌进入时计区。
5. **刷新点**：牌库耗尽时，将弃牌区洗回牌库，再将牌库顶一张直接放入时计区，然后继续当前伤害；该张即使是高潮也不取消本次伤害。若刷新点使时计区达到升级条件，应按照最终确认的规则时点结算升级。

### 2.3 输出

- 对方在整组伤害全部结算前败北的概率，使用百分比显示，并保留足够精度（内部用有理数或高精度数值，避免浮点累计误差）。
- 对方存活并完成全部伤害结算的概率（可显示为补数）。
- 可选的分段累计败北概率和规则说明，用于解释结果；首版至少应展示模型假设和规则版本。
- 显示计算模式为“精确枚举”，不使用随机模拟近似结果。

## 3. 规则分析与概率模型

### 3.1 两类卡牌的充分状态

首版把影响目标机制的卡牌归并为两类：高潮 `C` 与普通 `N`。在不包含卡牌效果、且每次洗牌均匀随机的前提下，不需要记录每张牌的身份或固定顺序，只需记录各区域两类牌数量。状态至少包括：

```text
(当前伤害序号, 当前伤害阶段（翻牌/命中后放置）, 待放入时计的命中普通牌数,
 牌库普通数, 牌库高潮数,
 弃牌区普通数, 弃牌区高潮数,
 时计区总数/高潮数, 等级区总数,
 当前伤害已翻普通牌数, 败北/存活)
```

时计高潮数必须纳入状态，以便在时计升级时正确决定被选入等级区的牌类别，并将其余卡牌正确移入弃牌区。升级选牌不是随机事件，而是对手决策；算法应比较合法选项的完整后续结果，选择使存活概率最高的动作。若当前等级为 3，任何升级都达到等级 4，应立即进入败北终态。

### 3.2 单次伤害结算

对声明伤害 `d`，逐张从牌库顶翻牌：

- 翻到普通牌：本段已翻普通牌数加一并暂存；达到 `d` 时确认命中，再按翻开顺序将本段普通牌逐张放入时计区。每放入一张后立即检查时计升级；升级后剩余时计进入弃牌区，尚未处理的本段普通牌继续放入升级后的时计区。
- 翻到高潮：立即取消本段；本段此前暂存牌和该高潮全部进入弃牌区。普通牌在取消时也进入弃牌区。
- 命中牌不是整批放入后才升级；每张命中普通牌单独进入时计并触发阈值检查，升级后尚未放入的命中牌进入新时计。每张牌进入时计后若达到 7，立即升级；若升级后等级达到 4，立即败北并终止本段及后续伤害。
- 刷新点是单独直接放入时计的牌；放入后立即检查时计是否达到 7，再继续当前伤害判定。

### 3.3 牌库耗尽和刷新

- 伤害判定需要继续翻牌但牌库为空时，若弃牌区为空，则依 `ws_rule.md` 判定对方立即败北。
- 若弃牌区非空，将其全部洗回牌库；牌库/弃牌区的高潮与普通数量同步迁移。
- 从洗后的牌库顶取一张刷新点放入时计区。刷新点可以是高潮，但此时不取消正在进行的伤害。
- 继续同一段伤害；直到翻到高潮取消、达到伤害数命中，或触发败北。

### 3.4 时计升级与败北

- 时计达到或超过 7 张后，依策略选择 1 张进入等级区，其余时计牌进入弃牌区。伤害命中后的每一张暂存普通牌都分别进入时计并触发阈值检查，因此一段较大的伤害可以在同一段结算中触发多次升级。
- 等级达到 4 立即判败；此后伤害序列剩余部分不再执行。
- **重要建模点**：若已有时计 `k` 张，命中 `h` 张或收到刷新点后跨越 7 张，可能触发升级。应按照规则逐次处理阈值，不可只对整组伤害总伤害点数作静态累计。

### 3.5 计算方法

采用精确动态规划/状态概率传播，不以蒙特卡洛作为首版结果。随机抽牌是按概率加权的随机节点；规则允许玩家选择升级牌时是决策节点，取使对手后续存活概率最大的动作：

1. 每个状态下，牌库顶为高潮的概率是 `牌库高潮数 / 牌库总数`，为普通的概率是 `牌库普通数 / 牌库总数`。
2. 对普通/高潮分支分别执行规则状态转移，并按对应概率累加到后继状态。
3. 当牌库刷新时，先把弃牌区的组成并入新牌库，再对刷新点卡牌按组成比例分支；其后续顶牌仍依据剩余牌库计数计算。
4. 合并完全相同的状态，用记忆化递归或逐层概率表计算，避免枚举实体牌排列。
5. 将所有败北终态概率求和，即为最优防守策略下的斩杀概率。刷新时弃牌区为空、或升级达到等级 4 均计入败北。

有限牌库且只有两种类别，状态规模远小于枚举所有排列；开发阶段仍需对最长伤害序列测量运行时间和状态数。如果实际支持范围导致状态膨胀，再考虑概率卷积、状态压缩或有明确误差标注的模拟模式。

**解析基准案例**：若不发生刷新、不发生时计升级，当前牌库有 `N` 张普通牌和 `C` 张高潮，单段伤害为 `d`，且 `N + C ≥ d`，则该段未取消（命中）的概率应为 `组合数(N,d) / 组合数(N+C,d)`，取消概率为其补数。此案例用于独立校验伤害取消概率分支。

## 4. 规则来源和首版范围说明

- 项目规则摘要：`docs/ws_rule.md`（伤害判定、刷新、时计结算和败北的首版工作规则）。
- 官方英文 WS 规则入口：<https://en.ws-tcg.com/rules/>；页面列出 Comprehensive Rules v2.10（2025-09-17）。
- 官方日文 WS 规则入口：<https://ws-tcg.com/rules/>；页面列出综合规则 v1.112（2026-08-24）。
- 官方新手规则说明：<https://en.ws-tcg.com/about/>，说明标准卡组 50 张且最多 8 张高潮、时计区最多 6 张且放入第 7 张时升级、等级区第 4 张败北。
- 官方规则 PDF 的网页抽取未能可靠取得正文。因此刷新点升级时点、伤害跨刷新暂存、连续攻击的精确检查时机，开发前应由熟悉规则的玩家/裁判对照正式规则复核，并把确认结论补充进 `ws_rule.md`。

首版只对输入的静态区域构成和伤害序列进行概率计算。卡牌效果可能改变伤害、移动牌、改变取消、改变时计/等级结算等情况均不纳入，除非后续单独增加明确建模。

## 5. 开发计划与交付物

### 阶段一：规则冻结与算例设计

**工作内容**

- 确认输入新增时计区高潮牌数量；确认升级选牌策略及刷新点触发升级的处理时机。
- 校对 `ws_rule.md` 中“刷新点、暂存伤害牌、时计升级、败北终止”的顺序；明确每段伤害完成后的状态检查。
- 定义合法输入范围、最大伤害段数/伤害值和已败北初始状态的处理。
- 为边界场景制作人工可推导的概率算例。

**交付物**：冻结版规则说明、字段定义、至少 10 个人工校验案例。

**完成标准**：每个输入字段均有确定含义；规则歧义有明确默认值或被排除在首版外。

### 阶段二：纯 Python 概率引擎

**工作内容**

- 建立 WS 计算模块，纯函数接收状态与伤害序列，返回结果，不依赖 Web 框架或前端。
- 实现伤害翻牌、高潮取消、刷新点、洗回弃牌区、时计升级、立即败北及剩余伤害停止。
- 使用精确有理概率或稳定的高精度数值，并对等价状态合并。
- 将状态转移和结果解释与 API、HTML 页面分离。

**交付物**：计算核心、状态转移说明、规则版本常量。

**完成标准**：人工算例全部通过；概率处于 `[0,1]`；相同输入确定性地产生相同结果；达到性能预算。

### 阶段三：测试与规则验证

**工作内容**

- 编写单元测试、边界测试和属性测试。
- 对小牌库状态枚举全部排列，与动态规划结果交叉验证。
- 测试刷新点是高潮/普通、伤害翻牌跨刷新、取消发生在刷新前后、时计达到 7 和等级达到 4 等路径。
- 对 `ws_rule.md` 中规则缺口形成明确问题清单并由规则审核者确认。

**交付物**：自动化测试集、规则核对记录和覆盖报告。

**完成标准**：测试覆盖所有状态转移；小规模穷举与概率引擎一致；无未解释的概率质量损失。

### 阶段四：Python API

**工作内容**

- 提供 `POST /api/ws/lethal-calculations` 接口。
- 使用请求模型校验字段、取值范围和区域数量关系；错误以稳定错误码和中文提示返回。
- 返回败北概率、存活概率、采用的规则/模型版本、计算假设及必要的分段信息。
- 首版不保存用户输入，不要求账号或数据库。

**交付物**：API、接口说明、接口测试。

**完成标准**：有效请求返回结果；非法输入返回清晰错误且不发生服务异常；接口测试通过。

### 阶段五：HTML/JavaScript 用户界面

**工作内容**

- 制作 WS 斩杀概率计算页面，以中文显示并支持桌面和移动设备。
- 提供牌库、牌库高潮、弃牌区、弃牌区高潮、等级、时计、时计高潮、伤害序列输入。
- 采用结构化输入（多段伤害可增删）并兼容 `2-2-3-4` 粘贴/解析。
- 展示主要败北概率、存活概率、已声明的假设和输入校验提示。
- 对 `等级-时计` 示例 `1-4` 给出清晰的标签，不仅依赖占位符。

**交付物**：可运行页面、前后端联调。

**完成标准**：用户按预期输入后可得到结果；所有验证错误可理解；移动端主要操作可用。

### 阶段六：验收与文档

**工作内容**

- 使用典型玩家输入进行端到端验收。
- 确认结果展示不会把“未被斩杀概率”和“败北概率”混淆。
- 更新项目 README 的启动说明及项目总设计文档。

**交付物**：MVP、中文使用说明、验收记录。

**完成标准**：从启动服务到输入 `2-2-3-4` 并读懂概率的流程完整可用；测试全通过。

## 6. 测试矩阵

至少覆盖下列情况：

1. 初始等级 3，命中升级后进入等级 4，立即计为败北。
2. 伤害翻到高潮取消，已翻普通牌与高潮进入弃牌区，不增加时计。
3. 伤害所需牌数刚好全部为普通牌，伤害命中并进入时计。
4. 牌库耗尽且弃牌区为空，立即败北。
5. 牌库耗尽且弃牌区有牌，正确洗回并取刷新点；刷新点高潮不取消当前伤害。
6. 伤害跨越刷新：刷新前暂存的伤害牌没有错误地混入刷新牌库。
7. 刷新点使时计从 6 到 7，验证升级选择和败北检查顺序。
8. 伤害序列中间达到败北，后续伤害不再处理。
9. 牌库高潮数为 0 或等于牌库总数时结果符合确定性预期。
10. 伤害值为 1、多个伤害段、空牌库/空弃牌区、计数边界与非法负数输入。
11. 小牌库穷举所有洗牌顺序，对照精确动态规划结果。
12. 每种输入情况下败北概率与存活概率之和为 1（浮点实现允许规定误差）。

## 9. 继续执行补充（本地规则基准）

本节是对前文“待确认问题”和阶段表述的执行性补充。遇到表述冲突时，首版实现按本节执行，同时在结果页披露假设；规则审核者确认后再修订规则版本。本计划只依据仓库中的 `docs/ws_rule.md`，不引用其他规则资料。

### 9.1 首版输入冻结

用户提出的“等级-时计”如 `1-4` 应解析为等级 1、时计 4；还必须增加“时计区高潮数”字段。推荐完整输入为：

```text
牌库总数、牌库高潮数
弃牌区总数、弃牌区高潮数
等级-时计、时计高潮数
有序伤害列表（支持 2-2-3-4）
```

时计高潮数不能省略或默认视为 0 后直接计算，因为时计升级时未进入等级区的卡会转入弃牌区，影响之后的洗牌概率。若界面初始填 0，必须提示用户确认实际数量。

输入校验统一如下：牌库/弃牌区计数为 0–50 的整数，高潮数不超过对应区域总数；等级为非负整数，等级不少于 4 作为已败北初态返回 100%；时计为 0–6，时计高潮数在 0 与时计数之间；伤害序列为非空正整数列表。输入代表当前牌库剩余数量，而非对局开始时的 50 张。已知区域总牌数最多 50、已知区域高潮数最多 8，但无需强制已知区域合计等于整副卡组张数，因为其余牌可能在未输入区域。拒绝负数、非整数、空伤害序列、高潮数大于区域数、超过标准构筑上限以及当前时计已达到 7 的未结算状态。

### 9.2 首版结算顺序（直接规则与建模约定）

1. 每次伤害逐张翻牌。普通牌先暂存；暂存普通牌达到该段声明伤害数时判定命中，再将暂存普通牌按顺序逐张放入时计区，并在每张后执行时计阈值检查。翻到高潮立即取消本段，所有本段暂存牌（包括该高潮）进入弃牌区。
2. 需要翻牌但牌库为空时，若弃牌区为空，立即计为败北并停止全部后续伤害；否则仅将弃牌区洗回牌库，再取一张作为刷新点放入时计区。刷新点无论是否高潮都不取消当前伤害。
3. **时计达到 7 后立即升级**：`ws_rule.md` 明确写“立即进行结算”。伤害取消判定结束且确认命中后，本段暂存普通牌按翻开顺序逐张放入时计；每放入一张后若时计达到 7，立即执行升级：防守方从当前时计选择一张进入等级区，其余当前时计牌全部进入弃牌区。该段仍未处理的普通牌继续进入升级后的时计，必要时再次升级。升级选牌依首版策略采用最有利于防守方存活的合法选择；选择是决策节点，不是随机抽牌。
4. 刷新点也会放入时计，故若刷新点使时计从 6 达到 7，首版先完成升级和败北检查，再继续本段伤害。这是从本地摘要字面顺序得到的可执行假设，尚不能视作经规则裁定确认的结论。
5. 升级达到等级 4 时立即败北；不再继续本段或后续伤害。每次升级只选择一张放入等级区，剩余时计全部进入弃牌区；若当前伤害仍有尚未放入时计的命中牌，败北前不处理它们。
6. 跨刷新时，本段已翻牌属于尚未结算的暂存牌，不加入弃牌区的刷新洗牌。只有本段命中或取消时才按结果转移。

第 3 项将“时计达到 7”按逐张立即检查处理：只有伤害确认命中后才将暂存普通牌逐张放入时计；取消时暂存牌按取消规则进入弃牌区。若同一段伤害余下的命中牌在一次升级后继续进入时计并再次达到 7，就再次升级。刷新点单卡进入时计时同样立即检查。伤害翻牌与命中后的时计放置是两个阶段，不能在尚未确认命中时先将翻牌放入时计，否则会错误处理高潮取消。

### 9.3 概率定义及算法交付

主要结果定义为：**从当前输入状态开始，按给定顺序处理伤害序列期间，对手在整组伤害完成前败北的概率**。败北包括等级达到 4 和牌库耗尽且弃牌区没有可洗回卡牌。另报存活完成概率；二者之和必须为 1。

首版升级选牌策略固定为“防守方最优生存”，结果页明确提示该假设。翻牌及刷新洗混均为随机过程；只追踪普通/高潮两类牌的分区数量，不追踪具体牌序。纯 Python 计算核心以不可变输入状态执行概率传播，优先使用标准库 `fractions.Fraction` 精确保留有理概率；相同状态合并。核心与 API、页面分离，不在此阶段引入框架或数据库。

内部状态至少包含：伤害序号、当前伤害阶段（翻牌或命中后放置）、本段已翻普通牌数、命中后尚待逐张放入时计的普通牌数、牌库普通/高潮数、弃牌区普通/高潮数、时计普通/高潮数和等级数。翻牌阶段的暂存牌不能提前进入时计；刷新时也绝不把暂存牌混入弃牌区洗回。进入命中后放置阶段时，按剩余待放置牌数逐张推进并在每张后检查升级。时计升级时须比较可选牌类别对完整后续结果的影响，而不是只看本次局部概率。

12. 合法随机输入概率范围有效、胜败概率和为 1；负数、超范围和区域关系冲突均返回输入错误。

## 10. 混合操作序列与摩卡支持

### 10.1 操作序列格式

伤害序列扩展为有序操作序列，数字仍表示普通伤害，`摩卡x` 表示摩卡查看操作。例如：

```text
2-2-3-4
摩卡2-3-摩卡2-3-摩卡3-3
```

前端同时提供操作构造器（添加伤害、添加摩卡、调整顺序、删除操作）和可编辑文本框。后端保留纯数字旧格式兼容，并接受结构化操作数组。

### 10.2 摩卡首版模型

- 摩卡 `x` 查看当前牌库顶最多 `x` 张；若剩余牌少于 `x`，只查看牌库现有卡牌。摩卡查看本身不进行牌库刷新。
- 看见牌后，操作方可以选择其中 0 至 `x` 张直接放入弃牌区；剩余牌按任意顺序放回牌库顶。之后序列中的操作按此已知牌顶状态结算。
- 被查看卡牌身份只区分普通/高潮；随机出现顺序按当前牌库中两类卡的剩余数量精确计算。操作方决策发生在看见实际牌之后。
- 默认摩卡操作方采取最有利于造成败北的合法选择（最大化对方败北概率）；等级升级选牌仍由防守方按最有利生存策略决定。两个决策节点均在结果假设中披露。
- 为限制排列分支，首版摩卡查看数 `x` 支持 1–10；随机看牌按普通/高潮数量合并等价观测，并只枚举保留牌的唯一类别顺序。超出范围时给出明确校验错误，不返回近似值。
- 查看操作不把牌从牌库移出；操作结束时丢弃选择进入弃牌区，保留选择进入牌库顶，未知牌库数量和已知牌顶队列分别记录，以免后续伤害抽牌概率错误。

### 10.3 新增验收用例

1. 混合序列 `摩卡2-3-摩卡2-3-摩卡3-3` 可被页面与 API 解析，概率总和为 1。
2. 摩卡看到高潮后可选将其放入弃牌区，后续伤害的取消概率相应改变。
3. 看牌顺序中存在普通/高潮两种排列时，后续伤害按操作方选择的剩余顶牌顺序结算。
4. 牌库剩余少于摩卡查看数时只看现存卡牌；空牌库摩卡不会触发刷新。
5. 结构化操作数组与文本格式得到相同结果；未知操作、零值及超过 10 的摩卡查看数明确报错。
6. 小牌库摩卡观察结果的精确概率分支及操作方最优选择经过独立穷举对拍。

## 11. 掏底操作支持

### 11.1 文本/API 操作格式

- `掏底条件x-y`：从牌库底部送弃 `x` 张；若本次掏底中出现至少一张高潮，则造成 `y` 点普通伤害。
- `掏底计次x-z`：从牌库底部送弃 `x` 张；每张被掏出的高潮各造成一次 `z` 点普通伤害。
- `x` 范围为 1–5；条件模式 `y` 范围为 1–4；计次模式 `z` 范围为 1–50（按普通伤害输入上限）。
- 结构化操作分别为 `{"type":"bottom_conditional","mill":x,"damage":y}` 和 `{"type":"bottom_per_climax","mill":x,"damage":z}`。

### 11.2 掏底状态转移

1. 每从牌底送出一张卡，立即放入弃牌区；普通/高潮数量分别跟踪，高潮计数属于本次掏底操作。
2. 如果继续掏底前牌库为空，且弃牌区有卡：将现有弃牌区（包括本次此前已掏入弃牌区的卡）洗回牌库，抽牌库顶一张刷新点直接入时计，执行正常时计升级检查；刷新点代表规则要求的 1 点伤害，不能再重复结算另一段 1 点普通伤害，然后继续完成本次尚未完成的掏底张数。
3. 刷新洗回的掏底牌仍可再次被从牌底掏出；高潮计数按本次操作实际掏出的卡次累计，卡牌若被洗回后又掏出，按再次掏出事件计数。刷新点不会取消本次掏底，刷新后继续掏底。
4. 若牌库与弃牌区均无牌可刷新，立即计为刷新败北，剩余掏底不继续。
5. 达到声明的 `x` 张后，条件模式只在高潮计数大于 0 时造成一次 `y` 点伤害；计次模式按本次掏出的高潮张数造成相同次数的 `z` 点伤害，次数不超过掏底张数 `x`（最多 5 次），没有额外 4 次上限。
6. 每次掏底伤害都按普通伤害流程独立判定（高潮取消、命中后逐张入时计）；某次被取消不取消之后尚待执行的计次伤害。

掏底中途刷新时，刷新点进入时计所代表的 1 点规则伤害只计算一次；不会在刷新点之后再额外翻牌结算一次罚伤。刷新点若使时计达到 7，先按时计规则升级，再继续掏底。计次模式每张实际掏出的高潮各触发一次伤害，次数受掏底张数限制，最多 5 次。

### 11.3 掏底验收

1. 无高潮的条件式掏底不造成后续伤害；至少一张高潮时造成声明伤害。
2. 计次模式按高潮计次，每次 `z` 点伤害独立处理取消。
3. 牌库底部掏牌遇到空牌库时，刷新点仅作为一次规则伤害进入时计且不取消掏底；不额外重复结算伤害，随后继续剩余掏底。
4. 刷新前已掏入弃牌区的卡会随弃牌区洗回，并可能在本次掏底中再次抽出和计数。
5. 牌库和弃牌区均空时立即败北；刷新点导致等级 4 时立即停止。
6. 用户示例：剩余牌库 2 张、掏底 4，刷新前后四张牌中只要含高潮就触发条件伤害。
7. x、y、z 边界、解析兼容、概率质量守恒和小牌库穷举测试通过。
